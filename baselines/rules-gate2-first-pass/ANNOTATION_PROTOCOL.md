# 正文标注协议 v1.1

适用新样本：GNU、NASA、GitHub 及后续快照。版本先于它们的首次预测冻结。旧 expected 不静默迁移；协议修订必须保留旧文件、哈希和对应报告。

## 内容范围

- 标题单独放 title，不重复放入 blocks；按语义识别，不能假定一定是 h1。
- 保留文章主体的解释、引语、参考链接文字、附录、实质修订记录、正文列表、代码、说明表格和脚注。
- 排除全站/页内导航、面包屑、作者日期等发布元数据、分享订阅、推广、推荐、反馈、联系记者信息及页脚。
- 文内的咨询小节按上下文判定，不根据邮箱、链接或 licensing 等关键词一律删除。
- 不做图片 OCR，不展开链接目标，不执行 JavaScript；图注单独标明纳入与否。

## 结构与文本

- 普通文字解码 HTML 实体并合并空白；代码保留原始换行和缩进。正文依 DOM 顺序保存。
- 每块都有 kind、text、list_type（无则 null）、depth（非列表为0）、ordinal（非有序列表为 null）。
- heading 保留原始 heading_level；code 不合并到相邻正文；table 的基础文本行以换行分隔、单元格以空格竖线空格分隔。复杂表格另记限制。
- 列表项可跨普通段落：首段为 list_item，后续独立段落为 list_item_continuation；嵌套 code 独立成块并带所属列表元数据；嵌套列表 depth 递增。列表内普通行内代码不拆块。
- description-list：dt 为 definition_term；dd 为 definition_description。一个 dd 若含多个 p，每段分别保留；内部列表另作 list_item，避免再次拼进描述导致重复。保持原始先后次序。
- footnote：独立保存正文说明，带 footnote_label 和 source_id；去除返回箭头、回跳编号；正文引用保留。可来源于普通 ol/li，不能因当前程序不支持而删去标准。
- paragraphs 是旧 p 视图：仅记录范围内的实际 p，保留其独立顺序；不把 dt/dd、列表裸文本或代码伪装成 p。块指标和旧 p 指标分别解释。

## 独立性与冻结

1. 审读原 HTML、确定范围；允许用独立 DOM 脚本辅助转录，但必须记录脚本和审核方式。助手标注不宣称为用户人工复核。
2. 标注脚本不导入生产提取器、生产块遍历或渲染函数；不先读预测再决定答案。
3. 保存 HTML/expected/协议/源码 SHA256 与时间，再首次预测；首次结果不可覆盖。
4. 因样本修改规则则该站点/模板转为开发用途；最终验证按完整站点保留，直到开发规则冻结后才评分。
5. 标注错误可修，但建立新版本并解释原因；首次旧报告仍保留。不同序列化协议带来的不匹配单列，不一概归为内容漏提。

GNU 范围决定：保留 History 的实质版本条目和 Footnote，排除页脚 Updated；该决定由助手根据原文执行，尚未收到用户对本页的逐项复核。
