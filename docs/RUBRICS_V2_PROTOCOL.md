# 项目三 Rubrics v2 评分协议

版本：2.0.0；冻结日期：2026-11-17。实现：src/webextractor/rubrics_v2.py。v1代码及历史报告保留。当前协议覆盖参考答案驱动的程序诊断，为下一阶段Qwen Judge定义分项、证据和未知状态；没有进行模型Judge或人工一致性校准。

## 输入与边界

输入候选title/blocks、可选gold、显式noise_terms及evidence_complete。每块包含kind/text，结构属性按kind适用。块索引从0开始，候选用p:N、gold用g:N。每文档最多2000块。gold缺失时分项为null/unscored，不能通过空参考答案得到满分。gold明确为blocks=[]与未标注不同；正文提取任务的空候选始终为critical。

完整性和纯净度统计中文字符、拉丁词、数字及标点的多重集合，重复预测不能增加召回上限；不能理解语义等价、顺序或否定关系，语义问题交给后续Judge。网页文本中的指令当作数据，不执行。

## 五个维度

| 维度 | 当前算法 | 已知边界 |
| --- | --- | --- |
| 完整性 | gold token多重集合召回；额外记录missing_tokens | 漏段/改写/拆合块需要结合证据解释，不能仅凭未对齐断言漏段 |
| 纯净度 | token精确率；每个显式噪声词的超额命中扣0.25，最低0 | 命中词须由评测者提供，大小写去重；gold中的合法出现不扣分；扣分系数未人工校准 |
| 结构 | 先按折叠空白的块文本一对一对齐，再比较适用属性；order_ratio为对齐gold索引最长递增子序列比例，分项取属性比例和顺序比例的较小值 | 无法对齐的文本不直接扣属性分，而降低coverage并标partial；相同重复文本按出现顺序配对，有歧义 |
| 标题忠实性 | 折叠空白后精确相同4分；仅丢开头章节数字3分；其他不同0分 | 未核验作者、时间、链接或来源归属；此维度不能据此声称来源忠实性已评估 |
| 格式 | 对齐代码块的kind与原始text精确比较，保留缩进、换行和末尾换行 | 仅代码格式；无代码时not_applicable/null；未对齐代码为unscored/partial；Markdown渲染、表格展示与链接尚未评分 |

结构适用字段：kind；heading的heading_level；list_item的list_type/depth/ordinal；footnote的footnote_label。source_id仅用于定位，不参与结构分。代码文本先忽略空白差异进行对齐，原始空白差异单独影响格式。普通段落只改文本不会直接扣对齐块属性分，但结构覆盖降低；段落换序由order_ratio检出。

## 分数锚点

连续比例分项统一使用以下诊断阈值，标题使用上表规则：

| 分数 | 比例范围 | 诊断含义 |
| --- | --- | --- |
| 4 | ≥0.98 | 按该程序指标几乎完全符合，不能代替语义正确结论 |
| 3 | ≥0.90且<0.98 | 小比例差异 |
| 2 | ≥0.70且<0.90 | 明显差异 |
| 1 | ≥0.40且<0.70 | 大幅差异 |
| 0 | <0.40 | 大部分不符合 |

阈值是v2开发基线，未经人工校准。后续不得根据冻结test调节阈值。分数与评估状态分开：scored、partial、unscored、not_applicable。evidence_complete=false时所有已得分维度改为partial；低覆盖不能被解释成高置信度。

## 问题证据与严重度

每条issue记录dimension/code/severity、p:N/g:N定位和最多200字符摘录，或全局对齐序列/标题前后值。噪声命中记录候选块位置；未对齐块注明可能是编辑、拆合或缺失，避免把自动匹配当作人工标签。

- critical：空候选。
- major：对齐块结构属性不符、顺序错误、代码空白/kind错误、显式噪声超额命中、非单纯编号的标题差异；未对齐且对应token召回/精确率<0.70。
- minor：其他未对齐差异、标题只丢数字编号。
- unknown：证据不完整。

这些严重度也是待校准规则，不等于已验证的人类严重错误分类。

decision只作为程序分流：有major/critical为fail；否则有issue或partial/unscored为uncertain；其余为pass。needs_human_review在有issue或未充分评估时为true。not_applicable不阻止通过。overall固定null，避免用平均分掩盖严重错误。不输出虚构置信度，不把该分数直接用作训练奖励。程序pass仅在声明范围内通过，不能代表链接/来源/所有语义均正确。

## 验收与下一节点

定向测试覆盖精确匹配、无gold、同类块乱序、文本替换、层级/列表属性错误、脚注标签与DOM id、代码缩进、重复块、提示注入样式文本、标题编号、证据缺失及非法输入。使用已保存Qwen结果进行离线复评，并保存输入/清单/实现SHA256。

节点2才实现Qwen Judge。Judge会接收网页证据、候选结果和rubric；有gold/无gold模式分开，要求可校验的DOM或block证据和无法判断原因。程序分与Judge分并存，不直接平均。节点3的人类标签必须由真实人工审阅产生；助手生成的标签只能标为silver，不能假冒多人金标。
