# DOM聚簇对照协议 v2

本协议在扩充页面首次运行相似度前保存；只使用开发页，不接触已评分web.dev验证。现有v1结果保留，不能覆盖。

## 对照组

固定阈值0.7，避免在同一小集合反复找阈值。对同一HTML/人工标签运行：

1. full-counts：完整标签路径及原始次数，沿用v1。
2. full-presence：路径是否存在，忽略次数。
3. full-capped：完整路径次数上限3。
4. semantic-presence：在full-presence上增加有限语义role上下文特征；仍排除正文、class/id/URL。以full-presence为直接对照，不将频次和role的共同变化归因于role。
5. suffix-capped：最多末3级标签路径，次数上限3，观察包装层不敏感带来的误聚。

执行前说明：初次实现另含suffix-presence（末3级路径去重），已对旧清单做内存烟测但未保存报告。扩展13页清单尚未评分；为落实原协议的次数上限3，补齐suffix-capped，正式五组使用以上命名。suffix-presence保留为可调用功能，不纳入本轮正式五组。所有模式参数固定，阈值仍为0.7。

这些是小规模开发特征消融，不报告泛化提升。不将最佳开发结果当测试集结论，也不降低阈值只为两篇Python文档合并。

## 人工标签与评测

保留新页面来源、哈希、完整HTML及结构范围笔记。分组先于分数：同站点不自动同模板；同模板也不自动保证规则兼容。每个同组应有真实结构证据。新清单明确同模板正例和同站点不同布局负例；有争议页单列标签理由。

逐对报告Jaccard、阈值连边、最终连通分量、人工同组、误聚和漏聚；另统计连通分量的链式风险。真实组与合成组分开，不能将两组页面对混成准确率。

至少复核两类反例：同模板长短页面是否被频次拆开；role变化/正文移出容器是否仍被误认为可复用。属性语义特征若改善其中一个反例，必须同时看其他页面，不能忽略结构仍接近但正文范围错误。

## 进入Agent的条件

有可复现代码、固定配置、真实多页对照、误聚/漏聚案例和复盘，明确当前聚簇仅产生候选共享组。后续在簇内参考页生成规则，仍需执行与跨样本质量检查，不直接把聚簇结果当奖励。

本阶段不要求所有页分组正确；单例过多、正例不足或新页下载失败须如实报告。后续采集独立新模板才能验证当前特征选择的泛化。
