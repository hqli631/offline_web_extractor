# 网页正文提取岗学习计划

## 当前起点与学习节奏

已经完成HTML/DOM与XPath基础，能够在VS Code中查看真实网页快照、手动定位容器、运行提取并检查结果。工程已支持候选评分、噪声清理、段落、列表、标题、代码、基础语义脚注及基础文本表格、单页/批量评测和固定XPath复用。当前52项测试通过；W3C修复后61/61结构块匹配；MDN仍有复杂列表协议差异。W3C与MDN都已用于调参，当前属于开发样本。Gate1—4的规则项目交付已完成；当前73项测试通过，Gate5 DOM聚簇原型已运行第一版并保留误聚/漏聚反例，尚需特征对照和更多同模板页。详见EXECUTION_TRACKER.md。

建议每个学习日1.5—2小时，按“5—10分钟讲解 → 你动手改一处代码或配置 → 运行并核对 → 记录错误和结论”的节奏推进。已有知识不重复做机械题，直接围绕实际输出练习。每次实现一个清晰目标，遇到新结构先判断是否在任务口径内，避免长期逐标签补洞。

## 短期：未来7—10个学习日完成规则提取项目

目标是做出一个范围明确、结果可复现、能解释失败原因的项目，再进入Agent。下面是学习日安排，不是要求连续自然日完成。

| 学习日 | 动手内容 | 当天验收产出 |
| --- | --- | --- |
| 1 | 检查三级标题与脚注：区分正文脚注和广告侧栏，核对引用编号与注释内容；当前不支持点击跳转 | 已完成；标题层级和脚注定向测试；旧网页回归通过 |
| 2 | 冻结提取规则，挑一篇新站点网页；先定义正文范围再看程序输出 | 已完成；W3C原始HTML、来源与哈希、人工标准答案、首次失败报告和修复报告均已保存 |
| 3—4 | 累积10—15篇快照，覆盖至少3种布局，如新闻、博客、文档 | 下一阶段；目前仍需新增6—10篇真实快照，并保留至少一个不参与调参的验证组 |
| 5 | 批量错误分析：容器找错、噪声混入、文字漏提、结构错误分别统计 | 逐页结果表和错误分类；挑最主要问题修复；保留修改前后报告 |
| 6 | 与一个成熟静态提取基线作公平对比，选择Readability或Trafilatura之一 | 在同一HTML、同一正文口径下比较结果；记录版本、耗时与适用范围，不只比较汇总分数 |
| 7 | 实验固定规则复用与模板漂移：参考页定规则，新页执行，不临时换规则 | 同模板成功/失败案例，匹配0个/多个时的回退设计；规则版本记录 |
| 8 | 整理项目说明、运行入口和实验报告 | 从新终端可复现的命令；代表性错误案例；包含数据划分与限制的报告初稿 |
| 9—10（机动） | 补标注分歧、修工程问题、复讲项目并清理冗余脚本 | 规则项目v1；5分钟项目叙述；一条有真实实验支撑的简历描述 |

短期过关标准：能独立保存网页、找正文边界、运行和修改提取器；能解释一处真实失败及修复；能区分规则命中率、完整性、纯净度、结构正确性；能说明哪些网页用于调参、哪些只用于最终验证。小样本结果必须同时报告样本数与来源，不给出无法支撑的工业准确率或成本收益。

如果一种复杂结构暂时投入过大，可明确列为不支持并记录状态，再推进评测与Agent主线。合并单元格、OCR、任意动态页面不应成为入门项目无限延期的原因。

## 长期：未来6—8周形成岗位相关能力链路

这部分从短期规则项目完成后开始。目标是能实现并评估小规模原型、读懂相关方法与工程权衡，不是数周内复刻工业平台。

| 阶段 | 核心内容 | 可验收产出 |
| --- | --- | --- |
| 第1周：结构与聚簇 | 从DOM提取标签路径、节点统计或布局特征；区分同站点与同模板；比较简单结构相似度 | 一份可解释的人工/算法聚簇对照；至少展示误聚与漏聚案例；按簇划分训练/验证 |
| 第2周：单Agent规则生成 | 调用Qwen API，根据少量参考页提出受限XPath配置；工具负责解析、执行、检查唯一匹配和反馈 | “生成 → 执行 → 反馈 → 修复”的可运行流程；先执行配置，不直接执行任意生成代码；设置步数、费用和超时上限 |
| 第3周：跨样本泛化与失败修复 | 一个规则在多个样本上验证；保留未见网页；记录修复是否损害旧页 | 与手写规则、无修复Agent的对比；成功率、调用次数、Token/费用、CPU耗时及失败原因 |
| 第4周：Critic与Rubrics | 设计完整性、纯净度、标题/列表/代码/脚注结构等评分标准；用人工小集合校准模型评委 | Rubrics文档、人工与模型分歧表；重复评分一致性；规则指标与模型评分联合使用 |
| 第5周：数据与SFT/LoRA | 整理“HTML证据—规则—执行反馈—修复”的轨迹；了解SFT与LoRA、QLoRA以及ms-swift流程 | 可检查的数据集与划分、训练配置、离线评估脚本；有资源再做小模型试训，资源不足先完成数据与评测 |
| 第6周：强化学习入门实验 | 学习策略、奖励、PPO/GRPO基本思想；把有限步规则搜索构造成小环境，观察奖励稀疏与投机行为 | 玩具任务中的轨迹/奖励日志；至少一个“分数高但正文差”的奖励漏洞案例；先理解再考虑训练扩展 |
| 第7—8周：可选深化与面试 | 根据岗位和资源选择Agentic RL、蒸馏或规模化CPU执行；阅读与实验结果互相验证 | 项目报告终稿、可复现实验、简历条目、面试问答与架构演示 |

多Agent不为角色数量而增加。先证明单Agent在哪些地方失败，再决定是否引入独立Critic、规划或搜索角色。模型评委的Rubrics评分也不能直接当成可靠奖励，需要与人工标注、规则指标和失败案例核对。

## 长期各阶段的执行拆分与闸门

| 闸门 | 按顺序完成的具体工作 | 进入下一阶段的条件 |
| --- | --- | --- |
| Gate 5：聚簇 | ①人工给同模板页分组；②提取去文本DOM路径/标签统计；③实现结构距离；④对照误聚、漏聚；⑤按完整站点/模板留出验证 | 有人工对照、可复现聚簇命令和失败页；跨页复用不依赖看过验证页 |
| Gate 6：单Agent | ①定义输入证据与JSON schema；②配置Qwen客户端；③生成容器/排除XPath；④本地执行并验证0/1/多匹配；⑤加入超时、调用与修复上限；⑥保存每步配置、观察、反馈 | 固定参考页可走通全流程，失败退出明确；先用录制响应验证流程，真实API调用前配置资源与预算 |
| Gate 7：泛化 | ①冻结参考页/测试页；②跑手写、无修复、有修复三组；③记录每页成功/失败；④统计调用次数、费用、CPU耗时；⑤观察修复损害旧页 | 相同数据与预算的三组报告；最终验证不参与选规则；不能只展示成功案例 |
| Gate 8：Rubrics | ①写完整性/纯净度/结构的等级锚点；②人工对照小集合；③模型盲评且隐藏方案名；④重复评分；⑤对照分歧；⑥检查网页文本诱导评分 | 人工分歧、模型稳定性与失败案例均有报告；评分不稳定时先修评估，不作为训练奖励 |
| Gate 9：SFT | ①收集真实执行轨迹；②去重并按模板切分；③清洗失败/修复样本；④选择SFT/LoRA/QLoRA；⑤准备ms-swift配置；⑥资源允许时试训并与基础模型对照 | 数据校验与评测可复现；只有实际训练并测试才报告训练收益；无GPU时标记训练未执行 |
| Gate 10：RL | ①构建有限动作与步数的规则搜索环境；②明确终止条件；③实现可解释奖励；④观察稀疏奖励与投机；⑤理解PPO价值基线与GRPO组相对优势；⑥资源允许再训练小策略 | 至少一组可回放轨迹、一处奖励漏洞及修正前后对照；不把玩具实验结论外推到工业Agentic RL |
| Gate 11：深化/交付 | ①按失败证据选一个方向；②做必要消融；③记录CPU批量解析/执行/缓存成本；④整理README与实验报告；⑤准备5分钟演示和简历描述 | 所有收益绑定数据切分、版本、命令和原始报告；若引入多Agent需证明额外角色的净收益 |

每次学习固定产出一条执行记录：本次目标、改动文件、命令、观察、失败类别、下一步。阈值在查看最终验证结果前约定；阶段验收以协议和证据完整为主，不要求把每个复杂网页修到满分。需要返工时回到对应闸门，保留旧报告和标注版本。

训练阶段遵循“先评测、再数据、后训练”。SFT、GRPO或蒸馏的效果需要独立实验支撑，不能仅凭流程名称推断提升；项目中的内部V6/V7、OPD等术语及其具体收益，需结合原始材料核对。CPU复用仍有解析、存储、执行与维护成本，学习重点是减少逐页模型调用，而不是宣称零成本。

## 贯穿全程的面试准备

每周整理一页记录：解决了哪个业务问题，为什么采用当前方案，失败案例是什么，如何验证修复，成本花在哪里。项目叙述按“任务和规模 → 基线 → 设计 → 关键错误 → 实验结果 → 局限与下一步”展开。

最终应能讲清：为什么同模板网页适合复用抽取程序；为什么容器匹配不等于全文正确；为什么同站点随机划分可能泄漏布局；如何发现模板漂移；为什么Agent生成规则需要执行反馈；如何校准评委及避免奖励投机。
